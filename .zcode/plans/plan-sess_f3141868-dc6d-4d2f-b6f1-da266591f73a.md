# Plan: Arreglos urgentes (seguridad + quick wins)

## 1. 🔴 Cerrar vulnerabilidad `SECURITY DEFINER` (migración SQL, vía Supabase MCP)

**Problema confirmado**: 20 funciones `SECURITY DEFINER` quedan ejecutables por `anon` y `authenticated` a través de `/rest/v1/rpc/`. La crítica es `activate_membership(uuid, uuid)`: un anónimo podría auto-activarse una membresía gratis.

**Qué hace el frontend hoy por RPC**: solo `expire_stale_memberships()` (en `admin-dashboard.tsx:36`, `Payments.tsx:35`, `MyMembership.tsx:35`). Las funciones `is_admin()` / `is_coach()` / `can_vote_routine()` se usan **dentro de políticas RLS** y deben conservar `EXECUTE` para `authenticated`.

**Migración** (`apply_migration`, nombre `revoke_security_definer_execute`):

```sql
-- Quita el grant implícito a PUBLIC + los roles que van por PostgREST
REVOKE EXECUTE ON ALL FUNCTIONS IN SCHEMA public FROM PUBLIC, anon, authenticated;

-- Regrant SOLO a lo que el app necesita en runtime:
GRANT EXECUTE ON FUNCTION public.is_admin() TO authenticated;
GRANT EXECUTE ON FUNCTION public.is_coach() TO authenticated;
GRANT EXECUTE ON FUNCTION public.can_vote_routine(bigint, uuid) TO authenticated;
GRANT EXECUTE ON FUNCTION public.expire_stale_memberships() TO authenticated;
```

> Los triggers (`handle_new_user`, `notify_*`, `activate_membership`, `apply_plan_duration`, `handle_payment_decision`, `set_payment_amount`, etc.) ejecutan como owner (definer), así que revocarles el `EXECUTE` a los roles no los rompe. `anon` queda sin acceso a ninguna función. Confirmo las firmas exactas con `pg_get_function_identity_arguments` antes de aplicar.

**Fix de `set_updated_at` (mismo tema de seguridad)**: `ALTER FUNCTION public.set_updated_at() SET search_path = '';` para eliminar el `search_path` mutable que avisa el linter.

No requiere regenerar `database.types.ts` (no cambia tablas/columnas, solo grants).
